# NH3 Sensor Analyzer

기존 `sensor_analysis_브라우저형_흰색스펀지.html`을 기반으로 만든 Windows 데스크톱 분석기입니다. HTML 화면·ROI·연구 분석 정의를 유지하면서 반복 영상 읽기와 픽셀 연산을 Python/OpenCV/NumPy로 분리했습니다. 인터넷 업로드 없이 원본 파일을 직접 읽습니다.

## 카메라 MP4 추출 중단 수정

일부 원본 MP4의 0바이트 영상 표본에서 OpenCV VideoCapture가 중단되는 문제를 수정했습니다. 영상 읽기는 PyAV/FFmpeg가 담당하고 OpenCV의 축소 보간·ROI·이미지 처리는 유지합니다. 시간 정보가 있는 빈 패킷만 건너뛰며, 실제 프레임의 PTS를 기록하고 중복 프레임은 추가 표본으로 세지 않습니다. 원본을 재인코딩하거나 누락 색상값을 채우지 않습니다. 요청 시각과 실제 시각 차이·표본 간격은 `video_metadata.sampling`에 기록합니다.

실제 8개 원본 연결(0.5 FPS) 추출과 기존 수식·보정·결과 저장 검사를 통과했습니다. 상세 범위는 `DECODE_VALIDATION.md`를 참고하세요. 아래의 이전 버전별 읽기 실패 기록은 수정 전 이력입니다.

## 새 대시보드

추출 중에도 Raw·Relative·Legacy 표시 모드를 바꿀 수 있습니다. 사용자가 고른 모드는 진행률 갱신으로 덮어쓰지 않습니다. White가 없거나 보정값을 계산할 수 없으면 선택은 유지하고, 현재 Raw 표시/데이터 대기 상태를 별도로 안내합니다. 보정 RGB/HSV 계산식과 추출 중 고정한 White·ROI는 그대로입니다.

지표 비교는 전체 농도 통합 순위입니다. 기존 농도별 점수를 동일 비중으로 평균하고, 평가할 수 없는 농도는 순위 점수에만 0으로 반영합니다. 원래의 결측 측정값은 채우지 않습니다. CV는 같은 농도 반복에서만 계산하며 서로 다른 농도의 반응 크기를 반복 불안정으로 취급하지 않습니다. 표는 순위·지표·점수·SNR을 간단히 표시하고, 화살표를 펼치면 변화량·Baseline SD·회복률과 평가 범위를 볼 수 있습니다. t90·회복 시간은 비교 표에서 제거했으며 분석·저장 데이터와 보고서의 농도별 부록은 유지합니다.

그래프의 X축·Y축 이름을 클릭하면 해당 축의 최소·최대 표시 범위를 설정할 수 있습니다. 기본은 기존 자동 범위이며, `자동 범위`로 각 축을 복원합니다. 그래프에 포커스를 둔 뒤 X/Y 키로도 열 수 있습니다. 범위는 화면 보기만 바꾸고 원본 표본·분석·CSV 수치는 변경하지 않습니다. 보고서용 별도 그래프는 기존 자동 범위를 유지합니다.

보라·파랑 파스텔 테마, 실제 NanumSquareRound Regular/Bold, 7단계 작업 패널을 사용합니다. **1센서 전용**이며 여러 영상 파일을 이어 읽는 기능은 유지합니다. 분석 ROI는 보라색, 독립적인 White Reference는 파란 점선입니다. 창을 최대화해 사용하면 영상·그래프와 설정 패널을 함께 보기 편합니다.

왼쪽 단계를 누르면 오른쪽 작업 내용만 바뀝니다. 중앙 영상·좌표·분석 데이터는 유지되며 메뉴 이동 때문에 재디코딩하지 않습니다. 1366×768에서는 긴 설정과 적용 버튼을 오른쪽 패널 내부에서 스크롤해 접근할 수 있습니다. 영상은 컨테이너 안에서 16:9 분석 좌표의 비율을 유지하며 강제로 늘리거나 자르지 않습니다.

`frontend/js/dashboard.js`, `frontend/dashboard.css`는 기존 DOM과 이벤트를 재사용합니다. Raw/Relative 선택은 기존 그대로이며 Legacy 메뉴는 이미 계산하던 `cal_*`(픽셀별 200/current White)를 선택해 보여 줍니다. 새로운 보정 수식은 추가하지 않았습니다. 흰 스펀지 수동 지정 버튼은 기존 Shift+클릭 진입 동작을 호출합니다.

폰트 원본과 OFL 전문은 `frontend/assets/fonts/`에 포함합니다. 설치나 외부 CDN이 필요 없습니다. 참고: [네이버 글꼴 안내](https://hangeul.naver.com/font).

## 실행

v1.4.3 미리보기는 선택한 영상 전체를 하나의 연속 시간축으로 표시합니다. 하단은 총 초와 시간·분·초, 상단은 전체 재생 위치/전체 길이입니다. 탐색 막대로 파일 경계를 넘거나 파일 목록에서 구간 시작으로 이동할 수 있습니다. 디코딩과 ROI 기준 프레임·사진은 원본 파일 안의 시각을 계속 사용하며 분석 시계열의 기존 시간 정의는 바꾸지 않습니다.

배포본은 **ZIP을 모두 풀고** 폴더 안의 `NH3SensorAnalyzer.exe`를 실행하세요. exe만 다른 곳으로 옮기면 작동하지 않습니다. Windows 10/11 64bit 및 Microsoft Edge WebView2 Runtime이 필요합니다. Python은 배포본에 포함됩니다. 첫 실행·바이러스 검사·PC 성능에 따라 시작 시간은 달라집니다.

소스 실행은 Python 3.14 64bit에서 `start.cmd`를 실행하거나 아래 명령을 사용하세요.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python app.py
```

1. **OpenCV 영상 선택**으로 같은 촬영 폴더의 영상을 고릅니다. 목록에서 순서를 확인하고 위/아래 버튼으로 바꿀 수 있습니다. 같은 이름의 다른 폴더 파일은 혼합하지 않습니다. `._` 메타 파일·복사본은 제외합니다.
2. 미리보기 장면을 고르고 **스펀지 클릭 선택**을 누른 뒤 분석할 스펀지 **중앙을 클릭**합니다. 두 개가 있어도 클릭한 하나의 윤곽만 잡습니다. 노랑 윤곽·주황 Edge·초록 최종 ROI를 확인하세요. 색·질감 분할이 불확실하면 검색 범위를 좁히거나 기존 수동 윤곽 지정을 사용합니다. 스펀지를 식별하는 대형 학습 모델은 넣지 않았습니다. 클릭한 부분의 기하 제안만 하며, 분석 픽셀의 색을 필터링하지 않습니다.
3. 기존 흰색 기준 드래그/흰 스펀지 잡기, Edge 비율/픽셀, 내부 회전 직사각형/윤곽 분석을 그대로 사용합니다. 한 번 고른 ROI는 추출 중 추적하거나 색으로 재선별하지 않습니다.
4. 디코더는 지원 시 자동 GPU 가속을 사용하며, CPU 모드도 선택할 수 있습니다. GPU/CPU 사이에도 디코딩 픽셀 차이가 있을 수 있으므로 반복 비교에는 같은 모드를 쓰세요. 실제 가속 방식은 파일 메타와 각 표본에 기록합니다. FPS, 주입·제거·회복 시각, 초기 White 구간을 설정하고 추출합니다. 기존 기본 FPS **0.5**를 임의로 바꾸지 않았습니다. 자동 시각 추정과 직접 입력도 기존과 같습니다.
5. 진행 중 취소하면 이미 추출한 표본을 보존합니다. CSV, Excel, 그래프, 설정 JSON, 보고서와 사진 기능은 기존 화면에서 사용합니다. 다운로드 저장 위치는 WebView2의 저장 대화상자에서 선택합니다.

## 역할 분담

| 영역 | 담당 |
| --- | --- |
| `analyzer.py` | FFmpeg 영상 디코딩, 960×540 축소, 선택 표본 추출, Float64 픽셀별 RGB/HSV·White 보정·논문 S·반응 픽셀·Edge 비교 |
| `app.py` | 파일 대화상자, 제한된 프레임 미리보기, 별도 작업 스레드, 진행률·취소·증분 결과, 반응 마스크 |
| `detection.py` | 사용자가 클릭한 스펀지 윤곽 분할 (색·질감/GrabCut) |
| `frontend/js/desktop.js` | 화면/엔진 연결, 비동기 결과 수신, 미리보기·스펀지 클릭 선택 |
| `frontend/js/core.js`, `timing.js`, `metrics.js`, `initial-baseline.js`, `research.js` | 시계열 통계·t90·회복·추천·실험 시각 및 지표 정의 |
| `frontend/js/roi.js`, `white-reference.js`, `calibration.js` | ROI 기하 편집·White 지정·보정 모드 선택 |
| `frontend/js/quality*.js`, `report.js` | 품질 검토·그래프·사진·보고서·내보내기 |
| `reference/original.html` | 사용자가 제공한 원본 스냅샷. 실행/배포에는 포함하지 않음 |

반복 픽셀 연산은 Python에 있고, 기하 계산과 표본 평균 시계열의 통계는 기존 JavaScript 정의를 유지합니다. 분석 정의를 한꺼번에 다시 쓰면서 발생할 회귀를 피하기 위한 선택입니다. 전체 분석을 Python으로 재작성했다고 표현하지 않습니다. ROI 각도 탐색은 기존 5° 후 상위 후보 근방 1° 방식이며 연속 각도 전역 최대를 보장하지 않습니다.

### v1.4.2 코드 정리

브라우저용 센서 자동 검출·픽셀별 RGB/HSV·White 기준 수집·논문 S·픽셀 Baseline/반응 마스크 계산의 중복 구현을 제거했습니다. ROI 평균색과 H 검산도 `Api.sample_frame`을 통해 실제 추출과 같은 `analyzer.sample`을 사용합니다. 마지막 미리보기의 RGB 프레임 한 개를 캐시하여 같은 장면의 색상을 읽을 때 재디코딩하지 않습니다. 지연된 색상 요청이 새로운 ROI 표시를 덮지 않도록 요청 순서도 확인합니다.

옛 브라우저 video 요소·파일 선택 핸들러·숨겨진 가중치 편집기·단일 테마를 다시 덮어쓰는 코드·빈 스크립트를 제거했습니다. 20개 JS 파일을 역할별 14개로 정리했습니다. 분석 지표 JSON과 추천 조합의 내부 가중치는 저장 호환에 필요하므로 유지합니다. 센서/White 기하 편집, White 스펀지 선택, 사진 그리기, 기준색 RGB↔HSV 변환과 시계열 통계는 화면 기능에 필요하여 유지합니다.

원본 HTML은 수식 독립 검증용이며 배포에 포함하지 않습니다. 소스 정리로 줄이는 JS 용량과 Python/영상 DLL을 포함한 배포 압축 크기는 구분합니다. 이 정리만으로 전체 배포 용량이 크게 줄어들지는 않습니다.

## 보존한 분석 규칙

- 원본과 같은 960×540 좌표와 letterbox, 프론트에서 확정한 정확한 pixel runs를 전달합니다. 분석을 위해 회전/warp하지 않습니다.
- Raw, 기존 200/White gain, 초기 White/current White의 Relative를 분리합니다. 픽셀별 보정→0~255 clip→HSV 순서와 채도 가중 원형 평균 H를 유지합니다. 양자화된 OpenCV uint8 HSV로 대체하지 않았습니다.
- White 여러 표본의 중앙값, 포화·암부 제외, White 미지정 시 Raw, 픽셀별 표본 SD와 엄격한 `>` 반응 판정, 3표본 연속 t90/onset 등 기존 정의를 유지합니다.
- FPS는 사용자가 정한 표본 간격입니다. 빠르게 만들기 위해 강제로 1fps로 낮추지 않습니다. 모든 프레임의 RGB를 UI로 보내지 않으며 압축된 원본을 통째로 메모리에 올리지 않습니다.
- 프레임별 요청 시각과 실제 디코더 시각을 모두 기록합니다. 디코더 timestamp가 불가능하면 frame index/FPS 근사임을 CSV에 표시합니다.

**동일 수식이 기존 영상 CSV와 비트 단위로 같은 값을 뜻하지는 않습니다.** 브라우저와 FFmpeg의 색 변환, GPU/CPU 디코딩, Canvas/OpenCV 보간 차이가 있습니다. 같은 RGB 입력에서 수식 일치 검사를 수행하며 디코더 변경은 설정 JSON에 기록합니다. 연구 결과를 교체하기 전 대표 원본 영상에서 기존 추출과의 차이를 검토하세요. 평활화·자동 ROI 이동·자동 이상치 제거는 추가하지 않았습니다.

# WebView2 통합 검사: 임시 합성 영상을 만들고 실제 창에서 추출/Excel 생성

`requirements-lock.txt`는 검증 환경 전체 의존성 기록입니다. 배포 크기/실행 시간/분석 속도는 실측값을 `VALIDATION.md`에 기록하며 30MB·1초 실행·10배 개선을 보장하지 않습니다. 무거운 ML/과학 그래프 패키지를 추가하지 않았습니다. 보고서용 한글 글꼴은 원본에 포함되어 있던 것을 유지했습니다.

오류 로그: `%LOCALAPPDATA%\NH3SensorAnalyzer\app.log`. 기본 동작은 영상을 읽기만 합니다. 영상·추출 결과·실험 설정은 Git에 자동 업로드하지 않습니다.

## UI 검증 (개발용)

`tests/serve_ui_test.py D:/video`는 localhost 테스트 어댑터이며 배포 앱에는 포함되지 않습니다. 출력 URL을 Playwright가 설치된 Node 환경에서 `node tests/ui_layout.cjs URL OUTPUT_DIR`로 열면 1920×1080, 1600×900, 1366×768 스크린샷 및 좌표·상태 유지 검사를 수행합니다. `PLAYWRIGHT_MODULE`로 별도 설치 경로를 지정할 수 있습니다. 테스트에 사용한 실험 영상과 스크린샷은 공개 Git에 저장하지 않습니다.

디자인 변경 전 기능 완성본은 Git 태그 `functional-baseline-v1`로 보존되어 있습니다. 분석 엔진과 API 파일은 해당 태그 이후 디자인 단계에서 변경하지 않았습니다.

## 최신 화면 조정

사용자 최종 요청에 따라 **가중치 조절 UI와 테마 전환 버튼을 제거**했습니다. 최종 보라·파랑 테마 하나를 사용합니다. 4단계 상단은 현재 최종 ROI 평균색이며, R/G/B 0~255·H 0~360°·S/V 0~100% 막대는 읽기 전용 실측값입니다. 값을 드래그해 원본 데이터를 바꾸지 않습니다. 기존 비교 기준색 편집은 고급 영역에서 구분해 접근할 수 있습니다. 과거 지표 JSON·추천 결과의 내부 계산/저장은 호환 유지합니다.

미리보기는 GPU 읽기 실패 시 CPU로 재시도하고, 실패 구간으로 이동했다면 마지막 정상 장면과 실제 시각을 유지합니다. 새 파일 첫 장면을 읽을 수 없으면 다른 파일의 이미지를 대신 보여 주지 않고 오류를 표시합니다. 한글/공백 PC 경로의 MP4 선택·PNG 미리보기·시간 이동 검사는 통과했습니다. 제공된 실험 파일 일부는 GPU·CPU 모두 첫 프레임 또는 초반 구간에서 읽기가 실패하므로 파일별 검증 기록을 참고하세요. 프로그램 미완성이라는 이유로 빈 화면을 정상으로 취급하지 않습니다.

## v1.2 구조 정리

최종 대시보드 구조를 `index.html`에 직접 배치합니다. 이전 화면의 헤더·메인 그리드, CSS 17개 및 이전 UI 글꼴 초기화 스크립트를 제거했습니다. `components.css`는 기능별 컴포넌트의 공통 규칙이고 `dashboard.css`는 최종 테마·레이아웃입니다. 분석 함수와 입력 ID는 호환 유지하되, 옛 화면 전체를 생성한 후 재배치하지 않습니다.

시작 단계는 영상 선택입니다. **영상 선택 → 조건 설정 → ROI 설정 → 3단계의 색상 추출 시작** 순서로 사용합니다. 중지와 진행률도 ROI 단계에 있습니다. White Reference 초기 좌표는 비어 있고 보정도 미설정입니다. 사용자가 배경을 드래그하거나 흰 스펀지를 지정한 경우에만 기준 영역을 활성화합니다. 이전 설정 JSON에 저장된 기준은 명시적으로 불러와 복원할 수 있습니다.

## 경량 빌드 재현 (Windows x64, Python 3.14)

앱에 필요한 OpenCV 모듈만 포함하는 선택 빌드입니다. 영상/ROI/색상 계산을 삭제하거나 수식을 바꾸는 방식이 아닙니다. 빌드 도구와 원본 소스는 배포 폴더에 포함하지 않습니다.

```powershell
.venv/Scripts/python -m pip install --target ../native-build-tools -r requirements-native-build.txt
.venv/Scripts/python packaging/build_minimal_opencv.py --workspace ../native-cv --tools ../native-build-tools --output ../lean-runtime
./build.ps1 -MinimalOpenCV ../lean-runtime
```

`./build.ps1`만 실행하면 공식 범용 OpenCV를 사용하는 표준 빌드입니다. 개발용 원본 HTML과 과거 디자인/라이브러리 빌드 자료는 EXE 데이터에 포함하지 않습니다. 보고서 내장 글꼴은 별도의 나눔고딕 사본 대신 UI의 NanumSquareRound R/B를 재사용하고, HTML을 저장할 때만 두 글꼴을 문서 안에 넣습니다.

EXE 자체의 독립 엔진 검사(현재 열려 있는 창에 영향을 주지 않음):

```powershell
./dist/NH3SensorAnalyzer/NH3SensorAnalyzer.exe --verify-videos "D:/video/실험폴더" --verification-output "검증결과.json" --verification-fps .5
```

이 모드는 오른쪽 스펀지 안의 고정 8,000픽셀·Raw로 읽기/시각/표본 범위를 검사합니다. 사용자가 편집한 ROI의 실험 결과를 대신하지 않습니다.
